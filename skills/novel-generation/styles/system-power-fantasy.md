# 系統流爽文風格 (System / Power Fantasy / LitRPG)

## 核心特徵

- 主角擁有**系統/面板/金手指**——成長可量化
- 核心體驗是**爽感**——升級、獲得、碾壓、打臉
- 爽感需要**節奏控制**——不是一直爽，要有低谷才有高峰
- 系統本身要有**限制和代價**——全能系統 = 無聊

## 系統設計原則

```
系統必須回答三個問題：
1. 它能做什麼？（功能邊界）
2. 它不能做什麼？（限制）
3. 使用的代價是什麼？（積分/壽命/任務/副作用）
```

| 系統類型 | 功能 | 常見限制 |
|---------|------|---------|
| 任務型 | 發布任務，完成獎勵 | 任務不可拒絕/有時限 |
| 商城型 | 用積分兌換能力/物品 | 積分難獲取 |
| 屬性面板型 | 量化能力值，可分配點數 | 點數有限 |
| 抽獎型 | 隨機獲得能力 | 結果不可控 |
| 模擬型 | 可預演未來/重置 | 次數有限/消耗巨大 |

## 爽感節奏模板

```
蓄力（被壓制/被看不起/遇到困境）
  ↓
觸發（獲得新能力/完成任務/升級）
  ↓
釋放（碾壓/打臉/震驚全場）← 爽點在這
  ↓
短暫平靜（收穫、被認可）
  ↓
新的壓制（更強的對手/更難的任務）
  ↓
重複，每輪規模更大
```

**3:1 法則**——3 份蓄力配 1 份釋放。蓄力越長，釋放越爽。

## 打臉場景設計

打臉是爽文的核心場景，但要避免低級打臉：

```
❌ 低級打臉：
「哼，你一個廢物也敢來？」
→ 主角一拳打飛 → 全場震驚

✅ 高級打臉：
對手有合理的看不起的理由（主角確實表面很弱）
→ 主角用對手最擅長的領域擊敗對手
→ 旁觀者逐漸意識到（而非直接喊出「不可能！」）
→ 留下伏筆（對手背後有更強的人）
```

## 數值膨脹控制

- 每個階段的數值範圍要**事先規劃**
- 避免無限膨脹——設定數值天花板或質變門檻
- 用**質的變化**代替**量的堆疊**（從力量 → 法則 → 概念）

## 品質檢查

- [ ] 系統是否有明確的功能邊界和限制？
- [ ] 爽感節奏是否有蓄力-釋放的節奏（非一直爽）？
- [ ] 打臉場景是否有鋪墊（非無腦碾壓）？
- [ ] 主角的成長是否同時有內在變化（非只有數值）？
- [ ] 數值膨脹是否受控？
- [ ] 系統的使用是否有代價？
